Duplicate File Manager

A local Flask web app that finds and safely manages duplicate files on your computer, using content-based comparison (MD5 hashing).

How it works

The scanner uses a multi-stage pipeline so it only hashes files that could actually be duplicates, keeping scans fast even on large folders.

Results & actions

Files with different sizes can never be duplicates, so they are discarded before any hashing happens. Of the remaining candidates, only the first 64 KB is hashed first – if those don't match, the full hash is skipped. This cuts unnecessary disk reads by most of the way.

Safety

Deleting the wrong file is irreversible. This app takes several precautions:

  • Files are sent to the Recycle Bin (via send2trash), never permanently deleted.
  • The server enforces "keep at least one copy" – the last file in a group cannot be trashed.
  • Every file is re-verified (exists + hash matches) immediately before it is trashed.
  • File paths are never accepted from the browser. The client sends IDs; the server looks up the real path from the stored scan result.
  • Every POST that modifies files is protected by a CSRF token (Flask-WTF).
  • The app binds to 127.0.0.1 only – it is not reachable from other machines on the network.

Tech stack

  • Python 3.13 + Flask 3
  • Flask-WTF for CSRF protection
  • send2trash for safe deletion
  • pytest for the test suite (14 tests)
  • Pure HTML + CSS (no framework) – design matches a Canva mockup

Why MD5?

MD5 is fast and more than accurate enough for finding accidental duplicates on a local disk. The probability of two different files having the same MD5 is astronomically low, and this app is not used in a security context where a malicious actor could craft a collision. If you are concerned, the code can be updated to use SHA-256 with a one-line change in detector/hasher.py.

Hardlinks

Two paths that point to the same file on disk (hardlinks) have identical content but are not duplicates – deleting one would destroy the only real data. The scanner deduplicates by (device, inode) so hardlinks are never reported as duplicates. On Windows NTFS, real inode numbers are obtained via os.stat() rather than the cheaper DirEntry.stat(), which returns 0.
